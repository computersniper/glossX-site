What the agent can do

Built for papers, not just prompts.

Tools, subagents and workflows designed around how research and learning actually happen.

✦

Literature review, verified

Plan, search, screen, read with reader subagents, check each claim against the paper span, then write a cited report. Team review adds a critic and a rebuttal round across several papers.

plan→read ×n→critic→verify→cited report
⎇

A workspace per paper

Every workspace is a git repository. The agent's edits become commits you can diff, branch, merge or revert.

◎

Learns how you learn

A learner model tracks concept mastery, so explanations and self-test questions meet you where you are.

⌁

A browser it can drive

Uses your Edge or Chrome over CDP with a live view and takeover. Downloads and imports ask first.

⌘

Commands, skills, hooks

Slash commands, @-mentions, SKILL.md skills, MCP servers and shell hooks, all as plugins.

Architecture

A small kernel.
Everything else is a plugin.

The kernel stays fixed and auditable. Tools, providers, subagents and workflows plug in through one manifest, and third-party output is always treated as untrusted data.

Results

Measured in the open,
against other agents.

Same base model, same task text, a fresh workspace per run and one scoring script for every system. Citations are checked against the PDF itself.

01

Benchmarks

SciFact claim checking, QASPER question answering, and GlossX-Route-100 for workflow routing. PaperArena, ScholarQABench and TutorBench follow.

02

Citation support

A judge model labels each quote SUPPORTS, PARTIAL or UNSUPPORTED. 20% is checked by hand; the rate counts only when κ ≥ 0.6.

03

Fault injection

A prompt-injection page inside a paper, a corrupted PDF, an unreachable model. The right answer is to refuse to make things up.

04

Compared with

Codex and pi on the same model and account, run headless with the same timeout. More agents can join through a command-line adapter.
